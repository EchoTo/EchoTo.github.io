上一篇写到，我用 Codex 那几个月不太顺，很多时候它理解不了我要做什么。但那是 3 月到 8 月的事，之后我一直在用 Claude Code，没再拿 Codex 做过什么。这个印象现在还对不对，我也不确定。

所以写了个小工具 [agent-race](https://github.com/TonkyShan/agent-race)，把同一个任务同时交给两个 Agent，各自在独立的 git worktree 里做，做完把两边的改动、耗时和测试结果放在一起看。

## 怎么比的

一开始先在博客和情报雷达上各试了一个小功能：文章页加阅读时间，雷达的 top 命令加一个按来源筛选的参数。

但这种需求太简单，看不出什么。后来从 Go 重构项目里挑了 5 个已经合进去的小改动：

1. 批量发 Kafka 消息时，失败被记到了别的消息上
2. 一个缓存键不存在时被当成异常，空闲的车每秒刷一条 WARN
3. 仿真传过来的车道号是数字，写进库变成了空
4. 日志推 Loki 时对方开了鉴权，要支持配置租户
5. 潮汐方向一直没变，时间戳却一直在刷新，车端以为潮汐变了

每个改动都先把代码退回到改之前，再像平时提需求那样写一两句话交给它们，比如第 2 个是「缺键是正常情况，不要打；真的 redis 出错还是要打」。每个任务后面都加了一句：只在本地改，不要提交，不要连服务器。

两边做完之后，把当年那次提交里的测试拿过来跑。这些测试它们事先看不到。

用的模型是 Claude Code 的 Opus 5.5 和 Codex 的 gpt-6-astra。

## 结果

| | Claude Code | Codex |
|---|---|---|
| 1. 失败记错了消息 | 58 秒，改对 | 412 秒，改对 |
| 2. 缺键刷 WARN | 73 秒，通过 | 533 秒，通过 |
| 3. 车道号变成空 | 77 秒，漏了一处 | 模型拥堵，没有改 |
| 4. Loki 租户 | 71 秒，通过 | 561 秒，参数顺序不同，编译不过 |
| 5. 潮汐时间戳 | 107 秒，通过 | 1129 秒，通过 |

第 1 题两边的测试其实都没过，因为当年的测试调了一个叫 `errsByRecord` 的函数，这个名字它们不可能知道。对照当年的改动看，两边找到的原因和改法都是对的。

Codex 走的是公司的网关，慢有多少是网关的原因，我分不清。前面雷达那个任务，Codex 第一次也是因为模型拥堵退出的，重跑了一次才做完。Claude Code 这 5 题一共花了 3 美元左右。

还有一点要说明：这 5 个改动当年都是我和 Claude 一起写的，测试里的函数名和参数顺序本来就是 Claude 的习惯，第 4 题 Codex 就是因为参数顺序不同没编译过。加上只有 7 个任务，我不打算拿这个比谁更强。

就结果来说，两边对需求的理解都没出问题，第 5 题这种和业务关系比较深的，我在任务里把是哪条消息、什么现象、新旧两种协议都要处理写清楚了，两边也都做对了。

比起谁对谁错，两边不一样的地方更值得看。

## 同一个需求，两种做法

雷达那个任务，我写的是：「top 命令加个参数，能只看某个来源的」。

Claude Code 的做法是筛选，只显示在这个来源出现过的条目，分数不变，同时在几个网站出现过的条目，加分也照样保留。Codex 的做法是只用这个来源的数据重新算分、重新排序。

两种都通过了测试，也都说得通。我写这句话的时候，根本没想过还有第二种理解。如果只交给一个 Agent，我大概率会直接用它给的那种，不会意识到这里有得选。

## 没说的，都没做

车道号那题是两边都没完全做对的一题。

当年修这个问题的时候，顺着同一个接口查下去，还发现另一个数字字段会被写成科学计数法，1717171717 进库变成了 `1.717171717e+09`，就一起修了。

这次我在任务里只写了车道号。Claude Code 修好了车道号，另一个字段没有动；Codex 那次正好碰上拥堵，什么也没改。

任务里没提到的，它们一般不会主动去找。当年能多查一步，是因为前面已经在线上踩过一次，知道这里的数据类型不可靠。

## 做完之后怎么交代

两边最后给我的说明也不太一样。

Codex 一般是列出改了哪几个文件、跑了哪些测试、结果通过。

Claude Code 会把没确认的地方写出来。第 1 题它说新加的测试没有拿旧代码跑过，结论是对着代码推出来的；第 4 题它加了租户的配置，但没有往任何环境里填值，说不知道实际的租户 ID，让我来定。

改动量大部分差不多，有两题差得比较多：雷达那题 Claude Code 改了 9 行，Codex 改了 35 行；第 5 题 Claude Code 加了 97 行，Codex 加了 176 行。

## 最后

这次之后，我觉得这个工具更适合用在需求本身没想清楚的时候。两个 Agent 做得一样，说明不了太多；做得不一样，往往是我自己的描述有问题。

agent-race 开源在 [GitHub](https://github.com/TonkyShan/agent-race)，可以拿自己的仓库试试。
